Specification

⚪ SIMULATION-FIRST ← Dashboard

A sports-market decision-support engine for MLB markets on Kalshi. It analyzes the entire board, ranks opportunities, tracks positions, calculates potential and realized pure profit (always net of fees), and learns from your historical decisions. It supports; it does not place trades or give real-money advice.

Core Pillars

The mission is not to pick winners — it is to answer, continuously: given the market, game state, bankroll, target, and my history, what's the best decision now? Eight pillars carry that:

Modes ✅ BUILT

Two completely separate modes. Simulation and live histories never mix.

1. Live Data Report 🔌 STUBBED

Real-world data only, from two sources:

  • Kalshi API — market prices, contracts, order book, positions, fills, market status.
  • Live MLB data — game status, score, inning, outs, pitchers, game state.

Never substitute stale, historical, estimated, or unrelated data for current Kalshi data. If live data can't be verified: mark it NOT VERIFIED, don't invent a value, don't use that market in the ranking, and explain what's missing.

2. Simulation Report ✅ BUILT

Hypothetical data only. Simulation results are never recorded as real performance and never touch the real bankroll, realized profit, or live record.

User Bankroll ✅ BUILT

Tracked: starting bankroll · current cash · total committed · current position value · unrealized pure profit · realized pure profit · target · target progress.

The default bankroll may be set by the user. Never invent a stake.

Action Ranking ✅ BUILT

Always scan the entire available board — not only games already selected. Rank strongest first: 🥇 #1, 🥈 #2, 🥉 #3, #4, #5 …

Each recommendation includes team(s), opponent(s), single/combo, game time, game status, current price, market probability, game state, historical fit, potential profit, risk/reward, why it ranked there, and the recommended next action.

The strongest recommendation is not automatically the highest-probability team. The ranking weighs market price, implied probability, game state, price movement, historical performance, entry price, potential profit, target availability, risk/reward, and single-vs-combo history.

Historical Decision Engine ✅ BUILT 🔌 live-fed

Uses your actual past live decisions to improve recommendations — team(s), single/combo, entry price, stake, ranking, decision selected, game state at entry, hold/exit/wait, target reached or missed, final result, realized pure profit, and unrealized profit at decision points.

It explains the reasoning in words, e.g. "Historically, your Single positions in this price range have performed better than your Combo positions."

Do not invent historical statistics. If there isn't enough data, say so. Simulation history is never included in live historical calculations.

Target System ✅ BUILT

Default target: +$5 pure profit. Continuously check whether it's realizable.

  • 1. TARGET NOT REACHED — best executable exit is still below target
  • 2. 🚨🎯 TARGET AVAILABLE — executable prices would realize ≥ +$5 now
  • 3. 🎯 TARGET LOCKED — worst-case outcome already ≥ target (a hedge)
  • 4. 🚨🎯 TARGET ACHIEVED — you actually banked ≥ +$5 realized
Never confuse unrealized with realized profit. A winning team is not a realized target.

Auto-lock (toggleable, default on): when the combined realizable profit reaches the target, the app automatically closes the minimal set of positions to bank it — one position alone, or several together.

Live Data Report Format 🗺️ PLANNED

Every live report contains, in order: header · bankroll · target · current positions · action ranking · target alert · position/P&L summary · profit tracking · your-decision area · full MLB board · data validation status.

Data validation labels

  • 🟢 KALSHI API VERIFIED
  • 🟢 LIVE GAME DATA VERIFIED
  • 🟡 USER-REPORTED
  • 🔴 NOT VERIFIED — if unverified, never present it as fact

Your Decision ✅ BUILT

Always offer numbered choices; the user can reply with just a number. Example:

  • 1 — Hold Dodgers
  • 2 — Hold Giants
  • 3 — Wait
  • 4 — Lock Dodgers target
  • 5 — Evaluate new opportunity

Record the decision and keep tracking.

Live Updates ✅ BUILT

Press u (or r), or click 🔄 Update, to regenerate the live report immediately. Session data is fully preserved — bankroll, positions, entry prices, stakes, and prior decisions all persist across updates and restarts; only Reset clears anything.

Game Closure & Post-Game Report 🗺️ PLANNED

When a game ends: FINAL → SETTLEMENT → REALIZED P&L → TARGET STATUS → HISTORICAL RECORD. Record in the live historical dataset; never overwrite previous snapshots.

Post-game report: team · market · entry · exit/settlement · stake · contracts · final result · realized pure profit · ROI · target status · decision ranking · whether the decision was historically consistent · lessons for next time.

Data Integrity Rules ✅ enforced

Never: invent Kalshi prices · invent scores · use yesterday's or tomorrow's market as today's · mix simulation and live results · claim potential profit is realized · invent historical performance · invent a stake · use stale search results when API data is available.

Every market must match by exact game, exact date, exact ticker.

If data fails validation: 🔴 DATA NOT VERIFIED — DO NOT RANK. Accuracy beats a complete-looking report.

Communication Style & Purpose

Be concise but decision-ready. Always surface teams, game time, single/combo, price, stake, profit, game status, ranking, and the next decision. Don't bury the recommendation.

The purpose is not to predict winners. It is: "Given the current market, game state, bankroll, target, and the user's historical decisions, identify the best available decision and explain why." Always separate Prediction from Decision from Profit from Realized Profit.
